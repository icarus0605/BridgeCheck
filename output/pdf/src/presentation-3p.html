명세와 Android·iOS·React 코드의
Bridge 이름 불일치를 배포 전에 찾습니다.

지금의 문제

  • 웹이 부르는 Bridge 기능을 앱 한쪽이 빠뜨리면 배포 후에야 발견됩니다.
  • 명세 표와 세 플랫폼 코드를 사람이 눈으로 대조합니다.
  • 누가 언제 고칠지가 메신저와 메모로 흩어집니다.

BridgeCheck

  • Bridge 명세서와 코드 파일을 브라우저에 올립니다.
  • ‘코드에 없음’·‘이름 불일치’·‘명세에 없음’을 파일과 줄로 보여 줍니다.
  • 담당자·수정 내용·개발/QA/운영 일정을 엑셀로 주고받습니다.

BRIDGECHECK · 담당자 관리와 한계

담당자별로 모아 보고, 정직하게 한계를 밝힙니다.

담당자 목록

  • 이름을 추가하고 항목마다 목록에서 선택합니다.
  • 빈 이름과 대소문자만 다른 중복 등록을 막습니다.
  • 담당자별 배정 건수와 미지정 건수를 보여 줍니다.
  • 이름을 누르면 그 담당자 항목만 봅니다.
  • 엑셀에서 불러온 담당자도 목록에 자동 반영됩니다.
  • 공유폴더에 담당자별 하위폴더로 엑셀을 저장합니다.

한계

  • 기능명·응답 이벤트 이름 대조입니다. 실제 앱 실행 통과를 보장하지 않습니다.
  • 필드·자료형·동적 이름은 분석하지 않습니다.
  • 담당자 목록과 일정은 탭 메모리에만 있어 새로고침하면 사라집니다. 엑셀로 저장하세요.
  • 실제 회사 공유폴더 저장은 아직 검증하지 못했습니다.

자동 검증: 계약 24묶음 + 코드 점검 13묶음 + 하네스 12상태 통과 · 실제 브라우저에서 샘플 흐름 확인
