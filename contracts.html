BRIDGECHECK / CONTRACT REVIEW

웹은 바뀌어도, 구버전 앱은 남습니다.

기존 앱과 변경할 웹의 연동 규칙을 비교하고, 배포 전에 확인할 변경을 찾아보세요.

실제 앱 동작 검증이 아닙니다.
변경할 웹 × 구버전 앱만 점검합니다. 구버전 웹(앱 내장 번들·캐시)은 범위에서 제외합니다.

1. 규칙 입력

웹 배포 전, 기존 앱에서도 잘 될까요?

앱 안의 웹 화면에서 카메라·로그인 같은 앱 기능을 호출하는 방식을 바꿀 때 사용하세요. 웹은 바로 바뀌지만 사용자가 앱을 업데이트하지 않으면, 새 요청을 이해하지 못할 수 있습니다.

예시: 웹에 ‘중간 화질’을 추가했는데 기존 앱은 ‘낮음·높음’만 알고 있는 경우입니다. 아래 버튼을 누르면 위험한 변경과 이유를 확인하고, 담당자·수정 방향·배포 일정을 적어 보고서로 전달할 수 있습니다. 준비한 파일 없이도 체험할 수 있습니다.

담당자 설정·보고서 만들기 →

가상 데이터입니다. 실행하면 입력·결과·대응 제안을 샘플로 바꾸고 파서 정책은 미확인, 전달 대상은 공통으로 설정합니다. 결과는 실제 비교 로직으로 계산합니다.

01 · 비교할 연동 규칙

① 기존 규칙 준비② 바뀐 부분 수정③ 점검하고 보고서 전달
입력값은 어디서 가져오나요?

웹·앱 담당자가 사용하는 Bridge 연동 명세나 실제 소스의 요청·응답 정의에서 가져옵니다. 실제 전송 데이터 한 건만으로는 필수 여부와 모든 허용값을 알 수 없습니다.

기존 앱이 주고받는 규칙을 기존 앱 연동 규칙에, 변경할 웹이 사용하는 규칙을 변경할 웹 연동 규칙에 넣으세요. 기존 연동 규칙만 있다면 복사한 뒤 바뀐 부분만 수정하면 됩니다.

처음 작성한다면 아래 작성 도우미를 쓰거나 담당자에게 action·응답 event·요청/성공/오류 필드별 이름·자료형·필수 여부·허용값을 요청하세요. 이 도구가 소스에서 자동 추출하지는 않습니다.

연동 규칙 작성 도우미 · 항목별로 입력하기

필드 이름과 자료형을 선택하면 연동 규칙 JSON을 만듭니다. 입력창에 반영을 눌러야 비교 대상이 바뀝니다. 도우미에도 원문이 표시되며 페이지를 닫으면 사라집니다.

string=문자, number=숫자, boolean=참/거짓, object=객체, array=배열. 허용값(enum)은 선택 사항입니다. 정해진 값만 허용할 때 JSON 배열로 입력하세요: ["low","high"], [0,1], [true,false]. 빈칸은 허용값 제한 없음입니다. object/array 내부 구조는 점검하지 않습니다.

각 영역에 필드가 없으면 빈 배열(제약 없음)로 반영합니다. 실제 명세와 일치하는지 확인하세요.

아직 비교 입력에 반영되지 않은 초안입니다.

팀 자체 단일 action 계약입니다. 원본 입력창에는 민감한 원문이 남습니다. 입력은 저장·전송하지 않습니다.

모르는 필드 처리 정책을 모르면 아래 설정은 미확인으로 두세요.

03 · 재검수와 테스트 예시

기존 앱의 미지 키·enum 처리, 변경할 웹의 누락 필드·자료형·구 event 수신 처리, 실제 구현과 계약의 일치 여부를 확인하세요. 변경 유예, 기존 형식 유지, 구형 응답 수용, 최소 앱 버전 게이팅을 검토할 수 있습니다. 필요한 최소 앱 버전은 사람이 결정합니다.

생성 예시는 실행 결과가 아닙니다. 민감 키의 값은 마스킹합니다. 모든 개인정보를 탐지하지는 않으므로 공유 전 검토하세요.

3. 담당자·보고서

공유할 점검 보고서

전달 대상 선택이며 OS별 판정이 아닙니다. 플랫폼별 계약·파서가 다르면 각각 입력해 재점검하세요.

담당자에게 전달할 대응 제안

오류·오류 가능·확인 필요 항목에만 제안을 선택합니다. 선택은 승인이나 수정 완료를 뜻하지 않습니다. 앱 변경은 업데이트를 설치한 앱에만 적용됩니다.

점검하면 여기에 핵심 내용이 표시됩니다.

담당자·일정·규격 메모는 직접 입력해 보고서로 공유합니다. 자동 수신·알림·공동편집은 지원하지 않습니다. 같은 요청의 같은 변경 항목을 다시 점검하면 메모를 이어받고 재확인 표시를 붙입니다. 초기화·샘플 전환·페이지 종료 시에는 지워지므로 먼저 다운로드하세요. 자유 입력은 자동 마스킹하지 않습니다. 비밀값을 넣지 말고 공유 전 확인하세요.

앱 배포 일정

개발 환경 → 품질(QA) 환경 → 운영 환경에 반영할 예정일입니다. 담당자에게 확인한 날짜를 아래 항목별로 입력하세요. 자동 수신·알림은 제공하지 않습니다. 보고서는 선택한 플랫폼의 모든 달 일정을 포함합니다.
