# BridgeCheck — 웹·앱 연동 변경 영향 점검기

이전·새 브리지 계약 JSON을 비교해 최신 웹과 구버전 앱 사이의 계약상 비호환 가능성을 정리합니다.

**실제 앱 동작 검증이 아닙니다.** 오류는 계약상 비호환 가능성의 검출이며, 실제 호환성과 배포 여부는 사람이 판단합니다.

## 1. 현재 상태

2026-10-23 기준 Prompt → PRD → 컨텍스트 정리까지 완료한 문서 저장소입니다. 제품, 하네스, 배포 주소는 아직 없으며 구현·실행 검증도 수행하지 않았습니다. 배포 주소는 후속 구현과 배포 후 제공할 예정입니다.

## 3. 실행 방법

**구현 예정**입니다. 현재 실행할 `index.html`은 없습니다. [이전 계약](samples/contract-v1.json)과 [새 계약](samples/contract-v2.json)을 읽고 [PRD §9](docs/02-prd.md#9-샘플-변경과-기대-결과)의 기대 결과를 확인할 수 있습니다.

후속 구현은 외부 라이브러리 없는 단일 `index.html`로 제공하며, 파일을 브라우저에서 열어 오프라인으로 실행하도록 설계합니다. 배포 주소에서도 같은 기능을 제공할 예정입니다.

## 4. 후속 범위

- 비교 화면, 입력 검증, 변경 탐지, 영향표, 테스트 예시, 보고서 복사 구현.
- 하네스 구축과 실제 검수, 코드 생성 검토, 배포 및 주소 제공.
- Skill 활용 여부와 근거 기록. 제품 내 AI는 후속 검토 범위이며 현재 기능이나 필수 실행 의존성이 아닙니다.

## 5. 제외 범위와 한계

최신 웹 × 구버전 앱만 점검합니다. 구버전 웹(앱 내장 번들·캐시), 다중 action, 중첩 스키마, 실기기 연동, 소스 분석, 실제 앱 호환성 확정은 제외합니다. 최소 앱 버전 게이팅은 대응 선택지이며 버전 번호를 추정하지 않습니다.

입력은 팀 자체 단일 action 계약입니다. `JSON.parse`의 중복 키 덮어쓰기와 큰 정수 정밀도 한계가 있습니다. 원본 입력창에는 원문이 남으며, 결과의 키 기반 마스킹이 모든 개인정보를 탐지하지는 못하므로 공유 전 사람이 검토해야 합니다.
