# BridgeCheck

Android·iOS·React Bridge 코드와 명세의 **이름 참조 후보**를 대조하고, 담당자별 수정 일정 엑셀로 전달하는 로컬 처리 도구입니다.

- 실행: https://bridgecheck.vercel.app/
- 발표 자료: [`output/pdf/bridgecheck-presentation-3p.pdf`](output/pdf/bridgecheck-presentation-3p.pdf) (3장)

## 1분 시연

1. 사이트에서 **샘플 적용** 버튼을 누릅니다. `samples/demo/`의 명세 엑셀과 Android·iOS·React 코드가 자동으로 들어가고 바로 점검됩니다.
2. 결과 29개 항목을 확인합니다. Android getLocation·iOS login은 `코드에 없음`, Android `share_result`는 `이름 불일치`로 나옵니다.
3. **작성한 일정 엑셀 불러오기**에 `samples/demo/2_담당자_일정_불러오기용.xlsx`를 넣고 반영합니다.
4. 담당자 목록에 김안드 4건, 이아이 3건, 미지정 22건이 표시됩니다. 이름을 누르면 그 담당자 항목만 봅니다.

샘플 파일은 사이트 상단 링크에서도 내려받을 수 있습니다. 직접 올려 보려면 `1_Bridge명세.xlsx`와 코드 파일을 각 입력란에 넣으면 됩니다.

## 결과 이름

| 결과 | 뜻 |
| --- | --- |
| 코드에 있음·동작 미확인 | 명세 이름을 코드에서 찾았습니다. 실제 호출·필드·실행은 확인하지 않았습니다. |
| 코드에 없음·누락 의심 | 명세 이름을 그 플랫폼 코드에서 찾지 못했습니다. 먼저 볼 항목입니다. |
| 이름 불일치·오타 의심 | 대소문자나 밑줄만 다른 이름이 있습니다. |
| 명세에 없음 | 코드에는 있지만 명세에는 없는 이름입니다. |
| 분석 못 함·직접 확인 | 지원하지 않는 문법이 있어 파일을 분석하지 못했습니다. |

## 기능

- **입력:** Bridge 명세서는 필수입니다. Android(Kotlin/Java)·iOS(Swift)·React(JS/JSX/TS/TSX) 중 코드 파일 하나 이상이면 점검합니다. 올리지 않은 플랫폼은 `미업로드·미검증`으로 표시하고 결과·일정 행을 만들지 않습니다.
- **명세:** XLSX/CSV에서 시트·기능명·응답 이벤트 열을 고르거나 JSON의 action/responseEvent를 씁니다. 명세 엑셀 양식을 내려받을 수 있습니다.
- **결과:** 근거 파일·줄, 검토 시작 위치와 제안을 보여 줍니다. 선택한 한 항목의 상세만 표시합니다.
- **일정:** 담당자·수정 내용·개발/QA/운영 예정일·진행 상태를 엑셀로 내려받고, 수정한 엑셀을 미리보기 후 반영합니다.
- **담당자 목록:** 이름을 추가하고 항목마다 목록에서 고릅니다. 빈 이름과 대소문자만 다른 중복은 막습니다. 담당자별·미지정 건수를 보여 주고, 누르면 그 항목만 봅니다. 엑셀에서 불러온 담당자도 목록에 들어갑니다.
- **저장 방식:** 담당자 목록과 일정은 브라우저 탭 메모리에만 있습니다. 새로고침하거나 탭을 닫으면 사라지므로 엑셀로 저장하세요. 엑셀에는 항목에 배정된 담당자만 저장됩니다.
- **공유폴더:** 데스크톱 Chrome/Edge에서 폴더를 고르면 담당자별 하위폴더에 엑셀을 저장합니다. 실제 회사 공유폴더 저장은 아직 검증하지 못했습니다.
- **이전 기능:** 이전↔새 JSON 계약 비교는 `contracts.html`에 남아 있습니다.

## 분석 범위

범용 컴파일러·실행 테스트·AI 코드 의미 분석기가 아닙니다. ‘코드에 있음’도 구현 완료나 통과를 뜻하지 않습니다. 명세 필드·자료형·요청/응답 내용은 점검하지 않습니다. 제한된 리터럴 호출/분기 패턴만 근거로 표시하며 실제 등록과 호출 경로는 사람이 확인합니다.

동적/조합/이스케이프 이름, Objective-C, 별칭, 문자열 안 JavaScript는 지원하지 않습니다. 정규식/나눗셈·템플릿·raw·다중행 문자열, 닫히지 않은 문자열/주석이 있는 파일은 보수적으로 ‘분석 못 함’으로 처리하며 화면·보고서에 사유를 표시합니다. JSX 닫힘 기호는 허용합니다. 실제 코드 표본으로 지원 패턴을 추가해야 합니다.

업로드 파일을 실행·외부 전송·영구 보관하지 않습니다. 결과 보고서에 원문 코드는 넣지 않지만 기능명·파일명·담당자명은 포함되므로 공유 대상은 사용자가 선택합니다. 공유폴더는 브라우저가 선택한 경로에 쓰는 기능이며 서버 저장·공동 편집·자동 동기화 기능이 아닙니다.

## 개발과 검증

```sh
python3 -m http.server 8769 --bind 127.0.0.1
node scripts/harness.cjs check
node scripts/harness.cjs status
```

발표용 시연 세트는 `samples/demo/`입니다. 화면의 ‘샘플 적용’ 버튼을 누르면 이 명세와 코드 파일을 자동으로 넣고 점검합니다. `1_Bridge명세.xlsx`와 세 코드 파일을 올려 점검한 뒤 `2_담당자_일정_불러오기용.xlsx`를 불러오면 담당자 목록과 일정이 채워집니다. `node scripts/make-demo-samples.cjs`로 엑셀을 다시 만들 수 있습니다. 3장 발표 자료는 `output/pdf/bridgecheck-presentation-3p.pdf`입니다.

`samples/codecheck/`는 의도적으로 getLocation 네이티브 처리가 빠진 정적 점검용 예제입니다. 컴파일 가능한 앱 프로젝트가 아닙니다. 예제 버튼으로도 같은 흐름을 체험할 수 있습니다.

기존 계약 회귀검사, 새 코드점검·엑셀·폴더 저장 테스트, 하네스 상태검사를 실행합니다. 브라우저 및 Claude 교차검토 증거는 `docs/05-implementation-check.md`에 기록합니다. 실제 OS 공유폴더 권한과 서버 동기화는 별도 사용자 환경 검증이 필요합니다.

SheetJS CE 0.20.3은 공식 `https://cdn.sheetjs.com/xlsx-0.20.3/package/dist/xlsx.full.min.js`에서 가져와 자체 호스팅합니다. 라이선스는 `scripts/codecheck/vendor/LICENSE`에 있습니다.
