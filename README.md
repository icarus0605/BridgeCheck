# BridgeCheck

Bridge 명세서에 적힌 **기능명과 응답 이벤트 이름이 Android·iOS·React 코드에 있는지** 찾아 주는 도구입니다. 빠졌거나 이름이 다른 곳을 파일과 줄 번호로 보여 주고, 담당자별 수정 일정을 엑셀로 정리합니다. 파일은 브라우저 안에서만 읽고 서버로 보내지 않습니다.

- 사이트: https://bridgecheck.vercel.app/
- 발표 자료: [`output/pdf/bridgecheck-presentation-3p.pdf`](output/pdf/bridgecheck-presentation-3p.pdf) (3장)

## 1분 시연

1. 사이트에서 **샘플 적용**을 누릅니다. `samples/demo/`의 명세 엑셀과 Android·iOS·React 코드가 자동으로 들어가고 바로 점검됩니다.
2. 2단계에서 결과 29개 항목을 봅니다. Android의 getLocation과 iOS의 login은 `코드에 없음`, Android의 `share_result`는 `이름 불일치`로 나옵니다.
3. 3단계에서 **작성한 일정 엑셀 불러오기**에 `samples/demo/2_담당자_일정_불러오기용.xlsx`를 넣고 **엑셀 일정 반영**을 누릅니다.
4. 담당자 목록에 김안드 4건, 이아이 3건, 미지정 22건이 나옵니다. 이름을 누르면 그 사람 항목만 봅니다.

샘플 파일은 사이트 위쪽 링크에서도 내려받을 수 있습니다. **간단한 예제 보기**는 짧은 코드 몇 줄로 흐름만 보여 줍니다.

## 화면 3단계

| 단계 | 하는 일 |
| --- | --- |
| 1. 코드와 명세 넣기 | 명세서(필수)와 코드 파일을 넣고 점검합니다. |
| 2. 결과 확인·일정 작성 | 항목을 하나씩 골라 설명을 읽고 담당자와 일정을 적습니다. |
| 3. 담당자·엑셀 전달 | 담당자를 추가하고, 엑셀을 내려받거나 불러오고, 공유폴더에 저장합니다. |

점검 결과가 있어야 2·3단계로 갈 수 있습니다. 입력을 바꾸면 1단계로 돌아가 다시 점검합니다.

## 결과 이름

| 결과 | 뜻 | 할 일 |
| --- | --- | --- |
| 코드에 없음·누락 의심 | 명세 이름을 그 플랫폼 코드에서 찾지 못했습니다. | 빠졌는지, 이름이 바뀌었는지 먼저 확인합니다. |
| 이름 불일치·오타 의심 | 대소문자나 밑줄만 다른 이름이 있습니다. | 명세와 코드 중 맞는 이름으로 통일합니다. |
| 명세에 없음 | 코드에만 있고 명세에는 없는 이름입니다. | 쓰는 기능이면 명세에 넣고, 아니면 코드를 지웁니다. |
| 분석 못 함·직접 확인 | 읽기 어려운 문법이 있어 파일을 건너뛰었습니다. | 파일을 직접 열어 확인합니다. |
| 코드에 있음·동작 미확인 | 이름을 찾았습니다. 실제로 동작하는지는 확인하지 않았습니다. | 급하지 않습니다. 필요하면 해당 줄을 확인합니다. |

목록과 엑셀은 Android → iOS → React 순이고, 플랫폼마다 먼저 확인할 항목이 위에 옵니다.

## 기능

- **입력:** 명세서는 꼭 넣어야 합니다. 코드는 Android(Kotlin·Java), iOS(Swift), React(JS·JSX·TS·TSX) 중 파일 하나만 있어도 됩니다. 올리지 않은 플랫폼은 `올리지 않음·점검 안 함`으로 표시하고 결과를 만들지 않습니다.
- **명세:** 엑셀이나 CSV에서 시트와 기능명·응답 이벤트 열을 고릅니다. JSON이면 action·responseEvent 값을 읽습니다. 명세 엑셀 양식을 내려받을 수 있습니다.
- **항목 설명:** 항목을 고르면 한 문장 설명, 할 일, 확인할 위치(파일 몇 번째 줄)를 보여 줍니다.
- **담당자 목록:** 이름을 추가하고 항목마다 목록에서 고릅니다. 빈 이름과 대소문자만 다른 같은 이름은 막습니다. 담당자별·미지정 건수를 보여 주고, 누르면 그 항목만 봅니다. 불러온 엑셀의 담당자도 목록에 들어갑니다.
- **엑셀:** 첫 시트 ‘요약’에 결과별·담당자별·플랫폼별 건수가 있습니다. ‘수정 일정’ 시트에 담당자·수정 내용·개발/QA/운영 예정일·진행 상태를 적어 다시 불러오면, 바뀌는 내용을 먼저 보여 준 뒤 반영합니다. 예전 열 이름(수정 위치·검토 제안)으로 된 엑셀도 불러올 수 있습니다.
- **공유폴더:** PC의 Chrome·Edge에서 폴더를 고르면 담당자 이름으로 하위 폴더를 만들어 각자 항목만 담은 엑셀을 저장합니다.
- **저장 안내:** 담당자 목록과 일정은 지금 탭에만 있어서 새로고침하면 사라집니다. 엑셀로 저장해 두세요. 엑셀에는 항목에 지정한 담당자만 들어갑니다.
- **이전 기능:** 예전 JSON 계약 비교 화면은 `contracts.html`에 있습니다.

## 할 수 없는 것

- 이름만 비교합니다. 주고받는 값, 자료형, 실제 앱 실행은 확인하지 않습니다. `코드에 있음`도 정상 동작을 뜻하지 않습니다.
- 이름을 따옴표로 직접 쓴 코드만 찾습니다. `"open"+"Camera"`처럼 조합하거나 변수에 담은 이름, Objective-C 코드는 찾지 못합니다.
- 정규식·템플릿 문자열·여러 줄 문자열이 든 파일은 통째로 건너뛰고 `분석 못 함`으로 표시합니다.
- 실제 회사 공유폴더 저장은 아직 검증하지 못했습니다. 공유폴더 저장은 서버 동기화가 아니어서 다른 사람 화면에 자동으로 반영되지 않습니다.
- 엑셀에 원문 코드는 넣지 않지만 기능명·파일명·담당자 이름은 들어갑니다. 누구와 공유할지는 사용자가 정합니다.

## 개발과 검증

```sh
python3 -m http.server 8769 --bind 127.0.0.1
node scripts/harness.cjs check
node scripts/harness.cjs status
```

- `samples/demo/`는 발표용 샘플입니다. 엑셀 두 개는 `node scripts/make-demo-samples.cjs`로 다시 만들 수 있습니다.
- `samples/codecheck/`는 getLocation 처리를 일부러 뺀 작은 예제입니다. 실제로 빌드되는 앱 프로젝트는 아닙니다.
- 하네스는 예전 계약 비교 검사, 코드 점검·엑셀·폴더 저장 테스트, 하네스 상태 검사를 실행합니다. 브라우저 확인 기록은 `docs/05-implementation-check.md`, 배포 기록은 `docs/08-deployment.md`에 있습니다.
- 엑셀 처리에 쓰는 SheetJS CE 0.20.3은 공식 배포본을 받아 함께 올려 두었습니다. 라이선스는 `scripts/codecheck/vendor/LICENSE`에 있습니다.
