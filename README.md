# BridgeCheck — 웹·앱 연동 변경 영향 점검기

이전·새 브리지 계약 JSON을 비교해 최신 웹과 구버전 앱 사이의 계약상 비호환 가능성을 정리합니다.

**실제 앱 동작 검증이 아닙니다.** 오류는 계약상 비호환 가능성의 검출이며, 실제 호환성과 배포 여부는 사람이 판단합니다.

## 1. 현재 상태

2026-10-23 기준 단일 `index.html` 초기 구현을 제공하며 계약 비교, 방향별 영향, 테스트 부분 예시, 보고서 복사와 Markdown 다운로드를 지원합니다. 로컬 HTTP 브라우저 확인과 비교 로직 검증을 진행했습니다. 배포하지 않았으며 실기기 동작은 검증하지 않습니다. 상세 실행·미실행 내역은 [구현 검증 기록](docs/05-implementation-check.md)을 확인하세요.

## 3. 실행 방법

`index.html`을 브라우저에서 여세요. 설치·빌드·외부 라이브러리가 필요하지 않습니다. 이번 자동화 환경에서는 `file://` 접근이 차단되어 해당 방식의 실제 브라우저 실행은 미검증입니다.

처음이라면 상단 **샘플로 바로 점검**을 누르세요. 새 화질 값·호환 변경·전체 변경을 실제 비교하며 가상 데이터를 사용합니다. 기존 입력·결과·제안은 교체됩니다.

1. **샘플 넣기**를 누르거나 이전·새 계약 JSON을 입력합니다.
2. 두 수신 파서의 미지 키 처리 정책을 선택합니다. 모르면 기본값 **미확인**을 유지합니다.
3. **변경 점검하기**를 눌러 영향과 근거를 확인합니다.
4. **보고서 전달 대상**에서 공통·Android·iPhone(iOS)을 고르고 위험 항목마다 대응 제안을 선택합니다. 대상만 바꾸면 기존 제안이 유지됩니다.
5. **Markdown 다운로드 (.md)**를 누르면 `bridgecheck-report-common.md`, `bridgecheck-report-android.md`, `bridgecheck-report-ios.md` 중 선택 대상의 파일로 저장합니다. **보고서 복사**도 사용할 수 있으며, 실패하면 읽기전용 보고서에서 직접 선택해 복사합니다.

다운로드는 화면의 마스킹된 보고서를 UTF-8 Markdown으로 저장합니다. 입력 문자열이 HTML이나 링크로 실행되지 않도록 본문을 코드 블록으로 감쌉니다.

샘플은 7개 변경이며, event 변경을 성공·오류 응답에 각각 표시해 결과는 8행입니다. 기본 설정은 오류 4행, 오류 가능 1행, 확인 필요 2행, 계약상 호환 1행입니다. 생성 예시는 변경을 분리해 검수하기 위한 부분 예시이며 실행 가능한 전체 메시지나 실행 증거가 아닙니다.

### 재현 가능한 로직 검증

Node.js가 있으면 저장소 루트에서 `node scripts/verify.cjs`를 실행합니다. 외부 패키지 설치 없이 실제 index.html의 스크립트를 읽어 10개 검증 묶음을 확인합니다. 검증 스크립트는 단일 인라인 script 태그를 전제로 합니다. 최소 DOM 대역을 사용하므로 브라우저·실기기 테스트나 제품 하네스를 뜻하지 않습니다. 제품 실행 자체는 Node.js를 요구하지 않습니다.

## 4. 후속 범위

- 오프라인 브라우저 실행 및 네트워크 차단 상태 검수 보완.
- 배포 및 주소 제공은 별도 요청 후 진행. 개발 하네스는 적용하며 자동 코드 생성은 필수 범위가 아닙니다.
- Skill 활용 여부와 근거 기록. 제품 내 AI는 후속 검토 범위이며 현재 기능이나 필수 실행 의존성이 아닙니다.

## 5. 제외 범위와 한계

최신 웹 × 구버전 앱만 점검합니다. 구버전 웹(앱 내장 번들·캐시), 다중 action, 중첩 스키마, 실기기 연동, 소스 분석, 실제 앱 호환성 확정은 제외합니다. 최소 앱 버전 게이팅은 대응 선택지이며 버전 번호를 추정하지 않습니다.

입력은 팀 자체 단일 action 계약입니다. `JSON.parse`의 중복 키 덮어쓰기와 큰 정수 정밀도 한계가 있습니다. 원본 입력창에는 원문이 남으며, 결과의 키 기반 마스킹이 모든 개인정보를 탐지하지는 못하므로 공유 전 사람이 검토해야 합니다.
