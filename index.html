수정 일정표로 전달하세요.

Android·iOS·React 코드에서 명세의 기능명과 응답 이벤트 이름을 찾아, 검토할 위치와 담당자별 일정을 엑셀로 정리합니다.

이름만 비교하는 도구입니다. ‘코드에 있음’은 이름을 찾았다는 뜻일 뿐, 기능이 제대로 동작한다는 뜻은 아닙니다. 주고받는 값과 실제 실행은 확인하지 않습니다.

‘샘플 적용’은 아래 샘플 파일을 자동으로 넣고 바로 점검합니다. ‘간단한 예제 보기’는 짧은 코드 몇 줄로 흐름만 보여 줍니다. 샘플 파일 받기: Bridge 명세 엑셀 · Android · iOS · React · 담당자 일정 엑셀

1. 코드와 명세 넣기

Bridge 명세서 + 코드 파일 하나 이상이면 점검할 수 있습니다. Android·iOS·React 중 필요한 것만 넣으세요. 올리지 않은 플랫폼은 점검하지 않습니다.

파일은 이 브라우저 안에서만 읽고, 서버로 보내거나 저장하지 않습니다. 새로고침하면 작성한 내용이 사라지니 먼저 엑셀로 저장하세요.

고른 두 열의 이름만 비교합니다. 다른 열은 읽지 않습니다.

플랫폼마다 파일 100개, 파일 하나 1MB, 코드 전체 5MB까지 올릴 수 있습니다. 테스트 파일과 빌드 결과물은 건너뜁니다.

어떤 코드를 찾나요?

아래처럼 이름을 따옴표로 직접 쓴 코드에서 찾습니다.

  • Android: @JavascriptInterface가 붙은 함수, action == "이름" 비교, when·switch 분기, emit("이벤트")
  • iOS: switch action이나 message.name의 case "이름", sendEvent("이벤트")
  • React: callBridge("이름"), window.Android.이름(), postMessage({action:"이름"}), addEventListener("이벤트")

찾지 못하는 경우도 있습니다. "open"+"Camera"처럼 이름을 조합하거나 변수에 담은 코드, Objective-C 코드는 확인하지 못합니다. 정규식이나 템플릿 문자열처럼 읽기 어려운 문법이 든 파일은 통째로 건너뛰고 ‘분석 못 함’으로 표시합니다. 이름을 찾아도 실제로 호출되는지는 사람이 확인해야 합니다.

3. 담당자·엑셀 전달


담당자 목록
담당자를 추가하면 2단계의 담당자 목록에서 고를 수 있습니다. 이름을 누르면 2단계에서 그 담당자에게 배정된 항목만 보여 줍니다.
    저장 안내: 담당자 목록과 일정은 지금 이 탭에만 있습니다. 새로고침하거나 탭을 닫으면 사라지니 엑셀로 저장하세요. 엑셀에는 항목에 지정한 담당자만 들어가고, 목록에만 추가한 이름은 들어가지 않습니다. 저장한 엑셀을 다시 불러오면 담당자 목록도 다시 채워집니다.
