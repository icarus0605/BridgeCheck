01 · 비교할 계약

① 기존 규칙 준비② 바뀐 부분 수정③ 점검하고 보고서 전달
입력값은 어디서 가져오나요?

웹·앱 담당자가 사용하는 브리지 연동 명세나 실제 소스의 요청·응답 정의에서 가져옵니다. 실제 전송 데이터 한 건만으로는 필수 여부와 모든 허용값을 알 수 없습니다.

기존 앱이 주고받는 규칙을 이전 계약에, 변경할 웹이 사용하는 규칙을 새 계약에 넣으세요. 기존 계약만 있다면 복사한 뒤 바뀐 부분만 수정하면 됩니다.

처음 작성한다면 아래 작성 도우미를 쓰거나 담당자에게 action·응답 event·요청/성공/오류 필드별 이름·자료형·필수 여부·허용값을 요청하세요. 이 도구가 소스에서 자동 추출하지는 않습니다.

계약 작성 도우미 · 항목별로 입력하기

필드 이름과 자료형을 선택하면 계약 JSON을 만듭니다. 입력창에 반영을 눌러야 비교 대상이 바뀝니다. 도우미에도 원문이 표시되며 페이지를 닫으면 사라집니다.

string=문자, number=숫자, boolean=참/거짓, object=객체, array=배열. 허용값(enum)은 선택 사항입니다. 정해진 값만 허용할 때 JSON 배열로 입력하세요: ["low","high"], [0,1], [true,false]. 빈칸은 허용값 제한 없음입니다. object/array 내부 구조는 점검하지 않습니다.

각 영역에 필드가 없으면 빈 배열(제약 없음)로 반영합니다. 실제 명세와 일치하는지 확인하세요.

아직 비교 입력에 반영되지 않은 초안입니다.

팀 자체 단일 action 계약입니다. 원본 입력창에는 민감한 원문이 남습니다. 입력은 저장·전송하지 않습니다.

모르는 필드 처리 정책을 모르면 아래 설정은 미확인으로 두세요.

03 · 재검수와 테스트 예시

구앱의 미지 키·enum 처리, 신웹의 누락 필드·자료형·구 event 수신 처리, 실제 구현과 계약의 일치 여부를 확인하세요. 변경 유예, 기존 형식 유지, 구형 응답 수용, 최소 앱 버전 게이팅을 검토할 수 있습니다. 필요한 최소 앱 버전은 사람이 결정합니다.

생성 예시는 실행 결과가 아닙니다. 민감 키의 값은 마스킹합니다. 모든 개인정보를 탐지하지는 않으므로 공유 전 검토하세요.

04 · 공유할 점검 보고서

전달 대상 선택이며 OS별 판정이 아닙니다. 플랫폼별 계약·파서가 다르면 각각 입력해 재점검하세요.
