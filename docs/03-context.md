# 03. 컨텍스트

## 1. 1차 안과 전환 사유

1차 안은 계약과 수동 시나리오를 대조하는 점검기였습니다. 계약 외에 웹 요청·Android 응답·iOS 응답을 준비하고 시연용 시나리오 3개까지 작성해야 하는 입력 준비 비용이 컸습니다. 수동으로 넣은 오타를 찾아주는 시연만으로는 실무 문제 해결 효과를 충분히 보여주기 어려웠습니다.

실제 사고의 핵심은 즉시 갱신되는 웹과 남아 있는 구버전 앱의 조합입니다. 따라서 기존 앱 연동 규칙과 변경할 웹 연동 규칙 두 개를 비교해 변경의 방향별 영향을 드러내는 도구로 전환했습니다. 반복 대조와 누락 감소가 목표이며 효과는 아직 측정하지 않았습니다.

1차 안의 [기획안·제작 프롬프트](legacy/웹뷰-브리지-점검기-기획안과-제작프롬프트.txt)와 [교차검토 기록](legacy/웹뷰-브리지-교차검토기록.txt)은 당시 상태 그대로 보존했습니다. 현재 제품 요구사항은 02-prd.md를 따릅니다.

## 2. 유지·변경한 결정

단일 action 계약 형식과 D·F절의 입력 검증·마스킹·안전 출력 원칙을 유지합니다. 계약+시나리오 입력은 이전+변경할 웹 연동 규칙 입력으로 바꾸고, 플랫폼별 예시 통과 여부 대신 변경할 웹 → 기존 앱 요청과 기존 앱 → 변경할 웹 응답을 구분합니다.

미지 키 처리 정책은 각 수신 파서에 대해 무시/거부/미확인만 선택하며 기본은 미확인입니다. 구웹 조합은 제외합니다. 오류는 계약상 비호환 가능성이며 실제 장애나 컴파일 오류를 확정하지 않습니다. 실기기 확인과 배포 승인은 사람이 맡습니다.

## 3. 개발 과정과 후속 범위

초기 문서 단계 이후 사용자 요청으로 단일 HTML 비교기와 대상별 보고서를 구현했습니다. Claude가 설계·코드를 검토하고 Codex가 실행 확인을 수행했으며, 구체적인 지적과 수정 결과는 05-implementation-check.md에 기록합니다.

교육 사이트의 실제 심사 조건을 확인한 뒤 첫 방문 체험과 검증 재현성을 보완했습니다. 임시 점검에서 재현 가능한 10개 로직 검증 묶음을 scripts/verify.cjs로 정리했습니다. 제품 하네스나 런타임 AI를 도입한 것은 아닙니다. 강의 자료 분석·발표 PDF 작성에는 PDF 스킬을 사용했으며, 제품 구현에 Skill을 필수 도입했다는 의미가 아닙니다.

공개 배포·실기기·업무 효과는 미검증입니다. 커밋 금지 지시는 유지하며 배포와 제출은 실제 확인 후 상태를 갱신합니다. 개발 목적의 별도 상세 문서는 사용자의 후속 지시 시 작성합니다.

## 개발 하네스 추가

이후 사용자 요청으로 scripts/harness.cjs를 추가했습니다. 자동검사·해시 기반 버전 확인·실제 Claude/Codex 수동 검토 기록·사람 승인 대기를 연결합니다. 제품 런타임 AI를 뜻하지 않습니다. 범위와 한계는 docs/07-harness.md에 명시합니다.

## 사용자 편의 개선

사용자가 입력값 출처를 물은 뒤 직접 사용자 관점의 개선을 요청했습니다. Claude와 복사·다음 행동 안내·출처 안내·파일 불러오기를 우선하고, 작성 도우미는 기존 parse를 재사용하는 접힌 폼으로 제한하기로 논의했습니다. 로컬 파일은 입력 revision과 선택 ticket으로 경합을 방지하며 원문 번들 내보내기는 이번 범위에서 제외합니다.


2026-10-23 추가 요구사항은 PRD §11을 따릅니다. 협업 메모는 판정과 독립된 일회성 수동 공유 기록이며 일정 자동 수신이나 규격 자동 변환은 아닙니다. 구현 범위는 화면·보고서·검증·현재 문서이며 기존 발표 PDF의 재제작은 포함하지 않습니다.

추가 요구사항 A7:A9는 PRD §12를 따릅니다. 단계별 날짜는 개발/품질/운영 환경 배포 예정일이며 달력은 수동 입력의 파생 화면입니다. 기본 담당자 적용은 명시적 버튼 동작이며 판정과 독립됩니다.

### 2026-10-23 추가 결정

사용자는 수작업 계약 JSON 비교의 시간 절약 효과를 지적하고, Android/iOS/React 코드와 명세를 넣어 검토 위치와 수정 일정을 정리하는 방향을 선택했습니다. 일정 산출물은 엑셀 표, 저장 위치는 선택한 공유폴더의 담당자별 하위폴더입니다. Claude의 설계 검토에 따라 이름 발견과 구현/실행 통과를 구분하고, 날짜 텍스트 왕복·안정된 행 키·덮어쓰기 확인·폴더명 검증·분석 제외 사유를 포함합니다. 공유 서버를 도입하는 요청으로 확대하지 않습니다.
