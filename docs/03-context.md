# 03. 컨텍스트

## 1. 1차 안과 전환 사유

1차 안은 계약과 수동 시나리오를 대조하는 점검기였습니다. 계약 외에 웹 요청·Android 응답·iOS 응답을 준비하고 시연용 시나리오 3개까지 작성해야 하는 입력 준비 비용이 컸습니다. 수동으로 넣은 오타를 찾아주는 시연만으로는 실무 문제 해결 효과를 충분히 보여주기 어려웠습니다.

실제 사고의 핵심은 즉시 갱신되는 웹과 남아 있는 구버전 앱의 조합입니다. 따라서 이전 계약과 새 계약 두 개를 비교해 변경의 방향별 영향을 드러내는 도구로 전환했습니다. 반복 대조와 누락 감소가 목표이며 효과는 아직 측정하지 않았습니다.

1차 안의 [기획안·제작 프롬프트](legacy/웹뷰-브리지-점검기-기획안과-제작프롬프트.txt)와 [교차검토 기록](legacy/웹뷰-브리지-교차검토기록.txt)은 당시 상태 그대로 보존했습니다. 현재 제품 요구사항은 02-prd.md를 따릅니다.

## 2. 유지·변경한 결정

단일 action 계약 형식과 D·F절의 입력 검증·마스킹·안전 출력 원칙을 유지합니다. 계약+시나리오 입력은 이전+새 계약 입력으로 바꾸고, 플랫폼별 예시 통과 여부 대신 최신 웹 → 구앱 요청과 구앱 → 최신 웹 응답을 구분합니다.

미지 키 처리 정책은 각 수신 파서에 대해 무시/거부/미확인만 선택하며 기본은 미확인입니다. 구웹 조합은 제외합니다. 오류는 계약상 비호환 가능성이며 실제 장애나 컴파일 오류를 확정하지 않습니다. 실기기 확인과 배포 승인은 사람이 맡습니다.

## 3. 개발 과정과 후속 범위

이번 회차는 Prompt → PRD → 컨텍스트 작성이며, 검토 요지와 샘플은 근거 자료입니다. Skill을 적용해 제품을 구현한 실적, 실행 가능한 하네스, 생성된 제품 코드, 제품 내 AI는 없습니다.

후속으로 화면과 비교 로직을 구현하고, 규칙표·입력 경계·마스킹을 확인하는 하네스를 구축한 뒤 오프라인 검수와 배포를 진행합니다. 코드 생성과 제품 내 AI는 후속 검토 범위이며 도입 결정이나 구현 완료를 뜻하지 않습니다. 배포 주소 작동, 업무 효과, 실제 실행 검수는 각각 증거가 생긴 뒤 기록합니다.
