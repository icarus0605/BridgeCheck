# 02. 제품 요구사항

## 1. 문제와 사용자

BridgeCheck — 웹·앱 연동 변경 영향 점검기.

React 웹뷰는 즉시 배포되지만 Android/iOS 앱은 스토어 업데이트를 기다리므로 구버전이 남습니다. 웹·앱 개발자와 QA는 브리지 계약 변경이 구버전 앱과 호환되는지 반복해서 수동 대조하며, 누락은 연동 사고로 이어질 수 있습니다. 이전·변경할 웹 연동 규칙의 차이와 방향별 근거를 정리해 재검수와 팀 간 전달에 활용합니다. 시간 절감과 사고 감소는 목표이며 측정된 실적은 없습니다.

## 2. 전제와 판정 경계

변경할 웹 × 구버전 앱 조합만 점검합니다. **구버전 웹(앱 내장 번들·캐시)은 이번 범위 제외**라는 안내를 화면과 보고서에 반드시 표시합니다. 기존 앱 연동 규칙은 기존 앱, 변경할 웹 연동 규칙은 변경할 웹이 준수하는 계약으로 가정합니다. 입력 계약이 실제 구현을 정확히 설명하는지는 사람이 확인합니다.

“오류”는 장애 확정이 아니라 **계약상 비호환 가능성 검출**입니다. 실제 앱 호환성 확정·실기기 연동·소스 분석·컴파일 검사는 수행하지 않습니다. 계약상 호환도 실제 앱 정상 동작 보증이 아닙니다. 오류 가능은 값 또는 생략 여부에 따라 비호환이 발생할 수 있다는 뜻이고, 확인 필요는 파서 정책 등 판단 근거가 부족한 상태입니다.

## 3. 입력과 비교 설정

기존 앱 연동 규칙 JSON과 변경할 웹 연동 규칙 JSON을 받습니다. legacy B절의 팀 자체 단일 action 계약 형식을 그대로 사용하며 네이티브 공통 표준으로 소개하지 않습니다.

| 속성 | 의미 |
| --- | --- |
| contractVersion | 계약 식별용 문자열, 앱 버전이나 호환성 판단 근거 아님 |
| action | 요청 액션명 |
| responseEvent | 응답 이벤트명 |
| requestFields | 요청 직속 필드 규칙 배열 |
| successFields | 성공 응답 직속 필드 규칙 배열 |
| errorFields | 오류 응답 직속 필드 규칙 배열 |
| 각 필드의 name/type/required/enum | 이름·자료형·필수 여부·선택적인 허용값 목록 |

동일 배열 안의 name으로 필드를 대응합니다. 필드 이름 변경은 삭제+추가로 표시합니다. 순서 변경은 의미 변경으로 보지 않습니다. 성공·오류 응답은 각각 비교하며 서로 섞지 않습니다. contractVersion 변경은 메타데이터 변경으로만 표시하고 호환성 오류로 만들지 않습니다.

비교 판정 설정은 다음 두 파서 정책입니다. 보고서 전달 대상과 대응 제안 선택은 판정을 변경하지 않습니다. 기존 앱 요청 파서의 미지 키 처리와 변경할 웹 응답 파서의 미지 키 처리를 각각 **무시 / 거부 / 미확인(기본)** 중 하나로 선택합니다. 두 파서는 독립 설정이며, 변경할 웹 응답 파서 설정은 성공·오류 응답에 공통 적용합니다. 무시=호환, 거부=오류, 미확인=확인 필요입니다. 기존 앱 버전별 자동 추정이나 별도 복잡한 정책 입력은 제공하지 않습니다.

## 4. 판정 규칙

| 변경 | 요청: 변경할 웹 → 기존 앱 | 응답: 기존 앱 → 변경할 웹 |
| --- | --- | --- |
| 필드 추가 | 필수·선택 모두 미지 키 처리에 따라 확인 필요(무시=호환, 거부=오류, 미확인=확인 필요) | 새 필수 필드=오류, 선택=호환 |
| 필드 삭제 | 구계약 필수=오류, 선택=계약상 호환 | 변경할 웹 미지 키 처리에 따라 확인 필요 |
| 선택→필수 | 계약상 호환 | 오류 |
| 필수→선택 | 오류 가능(변경할 웹이 생략 가능) | 호환 |
| enum 값 추가 | 오류 가능(기존 앱 허용 범위 밖) | 호환 |
| enum 값 삭제 | 계약상 호환 | 오류 가능(기존 앱이 삭제된 값 전송) |
| 타입 변경 | 오류 | 오류 |
| action/event 이름 변경 | 오류 | 오류 |

표의 action/event 변경은 이름 변경이 발생한 방향에 적용합니다. action은 요청, responseEvent는 응답의 식별자입니다. responseEvent만 바뀌었다고 요청 action까지 변경됐다고 표시하지 않습니다.

enum은 엄격 일치 집합으로 비교합니다. enum 제약이 새로 생기면 허용 범위 축소(값 삭제 방향), 사라지면 허용 범위 확대(값 추가 방향)로 처리합니다. 타입 변경 시 해당 필드의 enum 판정을 중복 생성하지 않습니다. 서로 독립적인 변경은 모두 보존하고, event 불일치가 있어도 다른 변경의 계약상 분석은 계속 표시합니다. 입력 검증 실패는 호환성 오류와 구분하며 비교를 중단합니다.

## 5. 출력과 사람의 판단

- 변경 목록: 필드 경로, 이전·새 규칙, 변경 종류를 표시합니다.
- 방향별 영향표: 요청, 성공 응답, 오류 응답별 판정·근거·적용된 미지 키 정책을 표시합니다. 확인 필요를 통과로 집계하지 않습니다.
- 재검수 항목: 기존 앱 파서의 미지 키·enum 처리, 변경할 웹의 누락 필드·타입·구 event 수신 처리, 실제 계약과 구현의 일치 여부를 사람이 확인하도록 안내합니다.
- 대응 선택지: 변경 유예, 기존 형식 유지, 변경할 웹의 구형 응답 수용, 최소 앱 버전 게이팅 등을 제시할 수 있습니다. 게이팅 필요 여부와 최소 버전 번호는 사람이 결정하며 도구는 번호를 추정하지 않습니다.
- 테스트 예시: 변경을 드러내는 요청·응답 예시와 기대 판정, 사람의 실행 확인 항목을 제공합니다. 생성된 예시는 실행 결과나 실기기 검증 증거가 아닙니다.
- 보고서: 두 계약 버전과 action/event, 비교 조합과 제외 범위, 파서 설정, 변경 목록, 방향별 영향, 재검수 항목, 테스트 예시, 사람의 판단·미검증 안내 순서로 구성합니다. 원본 JSON 전체는 포함하지 않습니다.

상단에 목적과 “실제 앱 동작 검증이 아님”, 두 입력창과 정책 선택, 점검·초기화·샘플 버튼을 배치하고 결과와 보고서를 이어서 보여줄 예정입니다. 보고서는 복사 가능하게 하되 실패하면 읽기전용 textarea에서 직접 선택해 복사하게 합니다.

### 5.0 빠른 체험 (2026-10-23 추가)
최상단 선택 메뉴와 버튼 한 번으로 가상 계약 입력과 실제 비교를 실행합니다. 새 화질 값 추가는 오류 가능 1행, 선택 응답 필드 추가는 계약상 호환 1행, 전체 샘플은 8행입니다. 실행 시 기존 입력·결과·제안을 교체하고 정책은 미확인, 대상은 공통으로 초기화함을 안내합니다. 최초 자동 실행과 초기화 후 자동 재입력은 하지 않습니다.

### 5.1 담당자 전달 보고서 (2026-10-23 추가)
- 전달 대상은 공통 / Android / iPhone(iOS) 단일 선택입니다. 대상은 제목·파일명·QA 대상만 바꾸며 판정 로직·파서 정책을 추정하지 않습니다. 플랫폼별 계약·정책이 다르면 각각 입력해 재점검합니다.
- 오류·오류 가능·확인 필요 행별로 미정 / 앱 변경 검토 / 웹 호환 처리 검토 / 변경 유예를 선택합니다. 선택은 미승인 제안이며 해결·완료·승인을 뜻하지 않습니다. 호환·정보 행에는 선택을 만들지 않습니다.
- 변경 종류와 방향에 맞는 앱 수정 검토 지점, React 웹 대안, 기존 앱 대응을 제공합니다. 실제 코드·API·수정 파일은 추정하지 않습니다. 기본값·자동변환·허용값 대체는 업무 의미 확인 없이 권장하지 않습니다.
- 앱 변경은 업데이트 설치 앱에만 적용되며 미업데이트 기존 앱 대응이 별도로 필요하다는 안내를 유지합니다.
- 대상 변경은 행별 제안을 유지하며 보고서를 갱신합니다. 입력·파서 정책 변경, 재점검, 샘플, 초기화는 기존 결과와 제안을 무효화합니다. 초기화 버튼은 대상도 공통으로 되돌립니다.
- 미리보기·복사·다운로드는 같은 본문을 사용합니다. 보고서는 요약·기존 점검 상세·대응 제안·대상별 QA·사람의 판단을 포함합니다. QA는 실제 브리지 확인 및 미업데이트/업데이트 설치 앱 각각의 검증을 안내하며 실행 증거로 표시하지 않습니다.

## 6. 입력 검증과 안전 출력

legacy 제작 프롬프트 D·F절을 재사용하되 시나리오 대신 두 계약 각각에 적용합니다.

### 6.1 계약 입력 검증

- 각 입력은 1,048,576 UTF-8바이트까지 허용하고 초과 시 파싱 전에 거부합니다. BOM 제거와 JSON 전체 trim만 수행하며 필드 값을 보정하거나 trim하지 않습니다.
- 최상위는 null·array가 아닌 object여야 합니다. 파싱 실패는 입력명과 고정 안내만 표시하며 네이티브 error.message와 원문 조각은 노출하지 않습니다.
- contractVersion/action/responseEvent는 공백만 있지 않은 문자열입니다. 세 필드 배열은 필수이며 빈 배열은 명시적으로 제약 없음입니다.
- 규칙의 name/type은 필수입니다. type은 string/number/boolean/object/array만 지원합니다. required 생략은 false, 지정하면 boolean이어야 합니다.
- name은 비공백 문자열이며 같은 배열에서 중복 금지입니다. 점·대괄호가 포함되거나 __proto__/prototype/constructor와 같으면 거부합니다.
- enum은 string/number/boolean에서만 지원하며 같은 type의 비어 있지 않은 배열이어야 합니다. nullable/maxLength 등 미지원 규칙 속성은 무시하지 않고 안전하게 속성을 안내하며 거부합니다.
- payload 직속 평면 필드만 지원합니다. object/array는 자료형만 나타내며 재귀 스키마·배열 요소·경로 해석은 미지원입니다. 속성은 own-property만 참조합니다.
- JSON.parse의 중복 키 덮어쓰기와 큰 정수 정밀도 한계를 README에 명시합니다.

### 6.2 테스트 예시의 값 규칙

legacy D절의 값 규칙은 후속 테스트 예시에도 유지합니다. 필수 키 부재는 오류이고 선택 키 부재는 검사 대상 밖입니다. 존재하는 null은 오류이며 0/false는 누락이 아닙니다. 필수 string의 빈 문자열은 오류이고 선택 string의 빈 문자열과 공백 문자열은 허용합니다. 자료형은 자동 변환하지 않습니다. object는 null/array를 제외하고 array는 Array.isArray로 판정합니다. 타입 불일치 시 enum 검사를 중단하며 enum은 엄격 일치입니다.

legacy의 “미정의 payload 키는 정보만 표시”는 이전 수동 예시 점검기의 정책입니다. 변경 영향 판정에서는 §3–4의 명시적인 수신 파서 정책을 적용합니다. 이번 입력에 수동 payload나 시나리오를 추가하지 않습니다.

### 6.3 마스킹과 출력

- password/token/authorization/secret/apiKey를 대소문자 무시 부분일치로 찾아 민감 키의 값과 하위 값 전체를 [MASKED]로 대체합니다. 필드명·경로는 유지합니다. 계약의 규칙 name이 민감 필드를 나타내면 연결된 enum 등 값에도 동일한 마스킹을 적용합니다.
- 입력 검증 안내, 기대값·실제값·추가필드 정보, 테스트 예시, 화면, 보고서 등 모든 결과 채널에 같은 정책을 적용합니다.
- object/array 실제값은 내용 대신 타입과 개수만 표시합니다. 문자열은 마스킹 후 최대 100코드포인트까지 표시하고 생략 여부를 알립니다.
- 원본 입력창에는 원문이 남는다는 안내를 표시합니다. 값 패턴으로 모든 개인정보를 탐지하는 기능은 아니며 공유 전 사람의 검토가 필요합니다.
- 입력을 코드로 실행하지 않습니다. DOM 출력은 textContent 또는 value를 사용합니다.
- 초기화는 입력·결과·보고서를 지우고 예시를 자동 재입력하지 않습니다. Markdown 다운로드는 고정 안전 파일명 `bridgecheck-report-common.md`, `bridgecheck-report-android.md`, `bridgecheck-report-ios.md`를 사용하며 다운로드 시도 후 Blob URL을 해제합니다. 입력에서 유래한 보고서 본문은 가변 길이 코드 펜스로 감쌉니다.

## 7. 실행과 배포 계획

단일 index.html에 CSS와 일반 JavaScript를 포함하고 file://에서 오프라인 실행할 예정입니다. 설치·빌드·서버·ES module·fetch·CDN·외부 폰트·라이브러리·API·분석 도구·외부 링크 자동 요청 없이 동작하도록 구현합니다. 모든 처리는 브라우저 메모리에서 하며 자동 저장·쿠키·localStorage·IndexedDB·Service Worker를 사용하지 않습니다.

초기 문서 작성 시점에는 구현 전이었으며, 2026-10-23 단일 index.html 초기 구현과 로컬 HTTP 검증을 추가했습니다. 현재 공개 주소는 https://bridgecheck.vercel.app 이며 배포 기록은 docs/08-deployment-check.md에 있습니다. 실제 실행·미실행 증거는 docs/05-implementation-check.md를 기준으로 합니다.

## 8. 범위와 검수 계획

초기 기획 범위는 Prompt → PRD → 컨텍스트와 기록·샘플 준비였으며 이후 사용자 요청으로 초기 구현과 전달 보고서를 추가했습니다. 이후 2026-10-23 사용자 요청으로 개발 하네스(docs/07-harness.md)를 추가합니다. 자동 코드 생성·제품 내 AI는 후속 범위입니다. 확인한 Skill 활용과 배포 증거만 별도 기록합니다.

후속 검수는 규칙표의 양방향 분기, 파서 정책 세 가지, 성공·오류 응답 분리, 입력 경계, 마스킹, XSS 안전 출력, 초기화, 복사 대체 경로를 대상으로 합니다. file:// 실행, 네트워크 요청 없음, 네트워크 차단 시 핵심 동작은 실제 브라우저에서 확인할 예정입니다. 실행·미실행 항목을 구분해 기록하며 미실행을 통과로 쓰지 않습니다.

다중 action, 중첩 스키마, 구웹 조합, 실제 앱 접근·콜백 실행·자동 수집·타임아웃 진단, 실제 앱 호환성 확정·실기기 연동·소스 분석은 이번 범위에서 제외합니다.

## 9. 샘플 변경과 기대 결과

[v1](../samples/contract-v1.json)은 legacy B절 예시 그대로입니다. [v2](../samples/contract-v2.json)는 아래 일곱 변경을 포함합니다. 추가 차이를 피하려고 contractVersion은 1.0 그대로 두었습니다. 이는 앱 버전이 아니며 같은 문자열이 호환을 의미하지 않습니다.

| 번호 | v1 → v2 변경 | 기본 설정에서 기대 결과 |
| --- | --- | --- |
| 1 | requestFields.quality enum에 medium 추가 | 요청 오류 가능: 기존 앱 허용 범위 밖 |
| 2 | requestFields.saveToAlbum 선택 → 필수 | 요청 계약상 호환 |
| 3 | 요청 timeoutMs(number, optional) 추가 | 확인 필요: 기존 앱 미지 키 정책, 무시=호환·거부=오류 |
| 4 | 성공 응답 thumbnailUrl(string, required) 추가 | 응답 오류: 기존 앱이 새 필수 필드를 보장하지 않음 |
| 5 | 오류 응답 message 삭제 | 확인 필요: 변경할 웹 미지 키 정책, 무시=호환·거부=오류 |
| 6 | responseEvent를 cameraResultV2로 변경 | 응답 오류: 기존 앱은 cameraResult 사용 |
| 7 | 성공 응답 photoId string → number | 응답 오류: 기존 앱 문자열과 변경할 웹 숫자 기대 불일치 |

후속 테스트 예시로 quality=medium 요청, timeoutMs가 포함된 요청, thumbnailUrl 없는 구형 성공 응답, message가 남아 있는 구형 오류 응답, event=cameraResult 응답, 문자열 photoId 응답을 제시합니다. 복합 샘플의 각 원인을 구분하고 개별 변경의 분리 검수도 수행할 예정입니다. 현재 표는 명세상 기대 결과이며 실행된 테스트 결과가 아닙니다.

## 10. 사용성 개선 (2026-10-23)

- 입력 출처(브리지 명세·실제 소스), 기존 계약 복사→변경 부분 편집→보고서 전달 안내. 실제 메시지 한 건에서 규칙을 추정하지 않습니다.
- 기존 앱 연동 규칙을 변경할 웹 연동 규칙으로 복사합니다. 원본 parse 검증 후 기존 변경할 웹 연동 규칙이 다르면 확인을 받고 반영합니다. 취소·오류 시 입력과 결과를 보존합니다.
- 로컬 JSON 파일: 읽기 전 File.size 1 MiB, 읽기 후 기존 parse 검증. 성공 시에만 반영하며 입력 revision·선택 ticket으로 늦은 파일 응답이 편집·초기화·새 파일을 덮지 않게 합니다. 외부 전송·자동 저장 없음.
- 접힌 작성 도우미: 이전/새 대상, 계약 식별자/action/event, 세 방향의 필드 행 추가·삭제, 이름/type/required/enum 입력. enum은 JSON 배열이며 타입 추정·변환 없음. 기존 parse를 유일한 계약 검증기로 사용합니다. 명시적 반영 전 초안은 판정에 사용하지 않습니다. 기존 최상위 추가 속성을 불러온 경우 보존합니다. 최대 150필드이며 큰 계약은 JSON 입력을 사용합니다. 초안 변경 후 불러오기·빈 초안 전환은 확인합니다. 전체 초기화는 도우미도 지웁니다.
- 결과가 없거나 무효화되면 복사/다운로드 비활성. 확인 필요만 있으면 정책 확인 후 재점검을 안내하고, 위험 변경은 근거 확인·대응 제안·전달을 안내합니다. 호환만 있어도 실제 기기 검증은 별도임을 유지합니다.
- 번들 내보내기·자동 추출·런타임 AI는 이번에 추가하지 않습니다.


## 11. 추가 요구사항 시트 반영 (2026-10-23, 시트1 A2:A6)

- 사용자 용어: 기존 앱 = 이전 규칙을 사용하는 설치된 앱, 변경할 웹 = 배포할 새 웹. 비교 입력은 각각 '기존 앱 연동 규칙' / '변경할 웹 연동 규칙'입니다. 판정 상태 이름과 비교 알고리즘은 유지합니다.
- 첫 화면에 앱 내 웹 화면의 카메라·로그인 호출 변경이라는 사용 상황과 화질 추가 예시, 파일 없는 체험 경로를 제공합니다.
- 보고서는 먼저 확인할 항목 → 협업 메모 → 대응 제안 → 상세 근거·테스트 예시 → QA 순서입니다. 화면에는 요약을 먼저 보여주고 원문·상세 대응·협업 입력은 접습니다.
- 위험 항목마다 Android/iOS 담당자·진행 상태·배포 예정일·목표 버전을 입력합니다. Android/iOS 보고서는 해당 플랫폼 일정만, 공통은 둘 다 포함합니다. 수동 입력이며 일정 자동 수신·알림·공동편집은 없습니다. 배포 완료 선택도 미업데이트 앱 해결을 뜻하지 않습니다.
- 규격 통일은 보고서당 한 번: 현재 Android 규격, 현재 iOS 규격, 통일할 규격, 조율 담당자, 합의 상태. 플랫폼 선택과 관계없이 함께 공유하며, 플랫폼별 실제 규칙이 다르면 각각 점검합니다. 메모를 자동으로 비교 입력에 반영하지 않습니다.
- 협업 입력은 일반 120자·규격 1000자 한도, 초과는 기존 값 보존과 안내. 날짜는 브라우저 date 입력값 그대로 사용하며 실제 일정 검증·추정은 하지 않습니다. 자유 입력은 자동 마스킹하지 않으며 UI와 보고서에서 명시합니다. textContent/value 및 가변 코드 펜스로 출력합니다.
- 입력 수정 시 결과는 무효화하되 직전 메모를 메모리에 보관합니다. 재점검시 기존/변경 action 쌍과 방향·필드·변경종류가 같은 위험 항목에만 메모를 이어받고 '재확인 필요' 표시를 남깁니다. 없어진 행의 메모는 다음 결과에 포함하지 않으며 그 뒤 재등장해도 되살리지 않습니다. 규격 통일 메모도 같은 action 쌍에 한해 이어받습니다. 대응 제안은 재선택합니다.
- 초기화·샘플 전환은 확인 후 메모를 지웁니다. 페이지 종료시 모든 입력·메모가 사라집니다. 보고서로 먼저 다운로드해야 하며 저장·동기화 서비스는 아닙니다.
